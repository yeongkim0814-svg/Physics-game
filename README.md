# 오픈월드 과학 탐험 게임 프로토타입

싱글 오픈월드 과학 탐험 게임의 웹 3D 프로토타입. 설계: `GAME_DESIGN.md`, 그래픽 기준: `OPEN_WORLD_ART_DIRECTION.md` §0. 현재(M1)는 허브 없이 곧바로 시작하는 샌드박스 맵에서 반동 이동(사출기)과 전도체 연쇄(전자기 코일)가 동작한다.

```
npm install
npm run dev     # 개발 서버
npm run check   # 타입체크 + 테스트 + 빌드 (커밋 전 필수)
```

## GitHub Pages 배포
`main` 에 푸시(병합)하면 `.github/workflows/deploy.yml` 이 `npm run check` 후 Pages 에 배포한다. 처음 한 번만 저장소 **Settings → Pages → Source** 를 **GitHub Actions** 로 둔다 (브랜치 선택 아님). 주소는 `https://<사용자명>.github.io/<저장소명>/`. 상대 경로(`base: './'`)라 저장소명을 코드에 적지 않는다. `gh-pages` 브랜치를 수동으로 만들지 말 것(Actions 배포와 무관).

## 튜닝 파일
- `src/config/tuning.ts` 게임플레이 수치 (반동, 연쇄 반경 …)
- `src/config/settings.ts` 비주얼(`VISUAL`), 성능(`PERF`), 터치(`TOUCH`) / `src/config/lowpolyPresets.ts` 시간대(황혼·낮) 프리셋 / `src/config/terrainParams.ts` 지형
- 실기기 검증 필요: 태블릿(Adreno 650+, Mali-G77+) FPS·자동 해상도(`PERF.targetFps`), 터치 감도(`TOUCH.lookSensitivity`)·버튼 위치(`TOUCH.buttons`)

## 사출기 튜닝 가이드 (T3)
모두 `src/config/tuning.ts` 의 `launcher` / `player`. 반동 Δv = m·v·recoil·recoilScale / 플레이어질량 (현재 투사체 2kg 로 약 8.6 m/s). 탄약은 무제한, 연사 간격만 제한.
- `recoilScale`(7.5): 반동 체감의 최우선 수치. 1.0 = 현실 운동량 보존(체감 거의 없음)
- `fireInterval`(0.4): 연사 간격. Δv 가 `중력×간격`(≈8 m/s)보다 크면 연사로 계속 상승, 작으면 활강. 현재 값이 거의 호버링이 되는 지점
- `player.recoilSlideTime`(0.45) / `slideFrictionMul`(0.08): 지상 반동 가속이 이어지는 정도
- `player.airAccel`(6): 공중 조작력. 낮을수록 반동 운동량이 보존됨
- `projectileGravity`(12), `spread.*`, `cameraKick`: 탄도/연사 퍼짐/시점 튐
- 투사체: `projectileMass`(2kg), `projectileColor`

**알려진 한계**: 실기기 조작감(터치 FIRE+JUMP 동시)은 미검증.

## 맵 (T4)
`src/data/map.ts` 한 파일이 레이아웃 전부다 (블록, 계단, 물웅덩이, 몹 스폰). 코드 수정 없이 좌표만 바꾸면 된다.
- 구역: 남쪽 스폰(평지+엄폐물) → 서쪽 물웅덩이 → 중앙 장애물 → 동쪽 금속 구조물(캣워크 3.6m, 금속 계단) → 북쪽 고지(6m, 계단 또는 반동 점프)
- 전도체: `GameWorld.conductors` 에 물/금속 노드 77개(`Conductor` 계약). 인접 노드 간격 ≤ 연쇄 반경이라 구조물 전체가 이어진다. `shock()` 하면 해당 구조물이 번쩍인다 (T6 코일이 사용)
- `GameWorld.isInWater(x,z)` 는 T6 누전 판정용, `mobSpawns` 는 T5 몹 배치용
- 계단 깊이는 캡슐 지름(0.7m) 이상이어야 한다. 계단 오르기는 `player.stepHeight`(0.5) / `stepProbe`(0.3)

## 몹 (T5)
`src/data/mobs.ts`(종류) + `tuning.mobs`(능력치·AI 거리/타이밍). 몹 수 상한은 `PERF.mobCap`.
- 금속: 튼튼·느림(HP60), **전도체**, 전기 ×2 / 절연: 빠름·약함(HP40), 비전도, 전기 ×0.25·물리 ×2 / 일반: 무특성(HP50)
- AI: 경계 거리(28m) 안에서 추적 → 1.3m 에서 정지 → 근접 사거리(1.7m)에서 **예고(0.35s, 몸이 부풀고 붉은 띠가 밝아짐)** → 그때까지 사거리 안이면 타격. 예고 중 벗어나면 헛스윙. 맞으면 경계. 계단도 오른다
- 모두 몸통에 붉은 발광 띠(적 기능색)가 있어 어두운 곳/올리브 배경에서도 식별. 종류는 실루엣으로 구분
- 몹은 `Damageable`(투사체)와 `Conductor`(코일 연쇄)를 동시에 구현. **피해 배율은 몹 내부에서 적용**하므로 호출측은 원 피해량만 넘길 것 (T6 에서 절연 배율 중복 적용 금지)
- 플레이어 HP 100, 낙하 피해 = (착지 속도 − 12) × 6 (10m 낙하 ≈ 48). 사망하면 스폰에서 부활

## 전자기 코일 (T6)
화면 위 **WPN** 버튼/F 키로 사출기와 전환. 수치는 `tuning.coil`.
- **충전**: FIRE 를 쥐면 충전(1.5s 에 100%), 충전 중 이동 ×0.35. 놓으면 방출, 15% 미만은 불발. 100% 를 넘기면 과충전(위력 최대 ×1.5), 150% 에서 자동 방출
- **연쇄**(`weapons/conductorGraph.ts`): 빔이 맞은 몹, 또는 맞은 지점 3m 안의 물/금속에서 시작. 구조물·물·금속 몹끼리는 연쇄 반경(6m), 플레이어·절연·일반 몹은 접촉 반경(2.5m) 안이어야 닿는다. 홉마다 피해 ×0.7, 최대 8홉. 절연/일반 몹은 맞기만 하고 전파하지 않는다. 한 노드는 최단 홉으로 한 번만 맞는다
- **누전**(막지 않음): 물 위에서 충전하면 초당 15×충전량 감전. 방출 시 발밑 물이 시작점이 되어 사용자에게 연쇄가 닿는다. 가까운 금속을 쏴도 6m 안이면 돌아온다. 팀킬도 같은 규칙.
- 맵의 금속 구역은 바닥 배관으로 29개 노드가 한 망이다
- 연쇄는 전도체 **근처**면 닿는다: 금속 배관 옆에 서 있는 일반 몹도 감전된다 (버그 아님)
- 알려진 한계: 번개 선이 저해상도에서 가늘다. 구조물 번쩍임이 주된 시각 단서

## 화면 안정화 (T8 수정)
- 계단: 올라설 때 3인칭 카메라 피벗이 부드럽게 따라온다 (`TUNING.camera.followSmooth`)

## 터치 입력 (멀티터치 · 전력질주)
`core/touch.ts` + 순수 판정 `core/touchMath.ts` (테스트됨), 설정은 `settings.ts` 의 `TOUCH`.
- **포인터 표**: 손가락(pointerId)마다 역할(move/look/fire/jump/swap)을 배정해 한 표로 관리. 시작만 터치 레이어에서 받아 **화면 좌표로** 역할을 정하고(버튼은 표시 전용), 이동/끝은 window 에서 받는다 → 포인터 캡처·이벤트 대상 요소에 의존하지 않는다
- 조이스틱 손가락(왼쪽 40%)과 시점 손가락은 독립. 조이스틱이 있을 때 왼쪽 영역의 두 번째 손가락은 시점. **FIRE 를 누른 손가락을 끌면 시점이 돈다**. 같은 버튼을 여러 손가락이 눌러도 모두 떼야 해제
- 놓친 `pointerup` 복구: touchend/touchcancel 때 실제 접촉 목록과 대조해 남은 포인터 정리. 포커스를 잃으면(알림/홈/탭 전환) 전부 초기화
- **화면 버튼은 `ui/tap.ts` 의 `onTap` 으로 처리**: 브라우저는 다른 손가락이 닿아 있으면(조이스틱을 잡은 채) 두 번째 손가락의 탭에 `click` 을 만들지 않는다. 그래서 같은 손가락의 pointerdown→pointerup 으로 직접 판정한다. FPS/FULL/TOUCH 버튼 모두 해당. 새 UI 버튼은 `click` 대신 `onTap` 을 쓸 것
- **TOUCH 버튼(화면 위)**: 진단 표시. 인식 중인 손가락과 역할(`touch 현재/최대`), down/up/cancel/healed/ignored 카운터를 보여준다. 기기에서 멀티터치가 안 될 때 이 화면을 캡처해 원인 확인
- **전력질주**(`touchMath.stepSprint`, 설정 `TOUCH.sprint`): 조이스틱 y(시작점 기준 위쪽 변위, 반경 대비)로 결정
  - y ≥ `start`(0.85) 가 되는 순간 전력질주 (속도 ×1.5). 이보다 약하게 밀면 걷기(아날로그). 손을 떼지 않고 `start` 아래로 내리면 해제
  - 전력질주 중 y ≥ `auto`(1.35, 림 밖까지)에 닿았다가 손을 떼면 **자동 전력질주**: 손잡이가 림 위쪽에 고정되고 손을 떼도 전진 유지. 자동 값에 닿은 뒤 `start` 아래로 내려가면 대기가 풀려 자동으로 이어지지 않는다 (`start`~`auto` 사이로 살짝 내려 뗀 건 인정)
  - **자동 전력질주 중 왼쪽(조이스틱) 영역을 다시 터치하면 취소**되고 그 터치의 조작을 따른다 (다시 y ≥ `start` 로 밀면 전력질주). 오른쪽 시점/버튼 터치는 영향 없음
  - 표시: 전력질주 중 손잡이 녹색 + 자동 전력질주 목표(▲▲)가 조이스틱 위쪽에 뜬다. 자동 값 도달 시 진한 녹색+진동
  - `hysteresis`(0.05)는 경계 떨림 방지. 코일 충전 중에는 속도 배율이 겹치지 않는다
- 데스크톱: Shift 를 누르는 동안 전력질주
- 터치 버튼은 FIRE / JUMP / WPN 이 있다 (AMMO 버튼은 재료 전환용이었으나 현재 미사용). 상호작용은 추후 설계 (키보드 E 입력만 `interactPressed` 로 남아 있음)
